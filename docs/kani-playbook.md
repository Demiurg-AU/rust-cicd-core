# Памятка по Kani: как доказательство не обманывает и не взрывается

Kani 0.68.0, Rust 1.100.0. Каждый приём ниже засвидетельствован в шаблоне или в закрытом
пилотном крейте. Статус указан у каждого пункта.

## 1. Правила ворот (`scripts/kani-gate.sh`)

Харнесс засчитывается, только если выполнены все три условия. Каждое условие проверяет своя канарейка (`kani-canaries.tsv`).

| Условие | Зачем | Канарейка |
|---|---|---|
| `VERIFICATION:- SUCCESSFUL` | доказательство прошло | **KC1**: внедрённая ошибка (`wrapping_add` вместо `checked_add`) → `verification failed` |
| **все** cover-проверки SATISFIED, и их ровно столько, сколько указано в конфиге | доказательство не пустое | **KC2**: `kani::assume(false)` в начале харнесса |
| каждый `#[kani::proof]` в `src/` есть в `kani-harnesses.tsv` | нет тихого пропуска | **KC3**: харнесс, которого нет в конфиге, → `unlisted harness` |

**Главное свидетельство (VERIFIED_PRIMARY, канарейка KC2).** На пустом доказательстве Kani
сообщает `Complete - 1 successfully verified harnesses, 0 failures`. Пустоту видно только по строке
`** 0 of 2 cover properties satisfied (2 unreachable)`. Ворота, которые смотрят лишь на
SUCCESSFUL, принимают доказательство «ничего».

Для крейта-потребителя нужна только конфигурация: свои `kani-harnesses.tsv` и `kani-canaries.tsv`.
Скрипт ворот менять не нужно.

## 2. Почему формула взрывается

- **`#[kani::unwind(N)]` ограничивает все циклы сразу**, включая memcmp внутри сравнения строк.
  Длинные строки в харнессе вынуждают поднять N. Вложенные циклы (обход реестра × сравнение строк)
  перемножают объём, и CBMC падает по памяти ещё до SAT-решателя (VERIFIED_PRIMARY: в пилоте раннер
  убивался при `unwind 8`, а при строках ≤ 2 символов и `unwind 3` доказательство укладывалось
  в 50–150 с).
- **Смена SAT-решателя (kissat, cadical) не помогает**, если формула раздувается до SAT
  (CONTRADICTED как средство).
- **Не поднимайте `unwind` вслепую.** Assertions развёртки включены: недостаточная граница даёт
  FAILED, а не ложный SUCCESS. Это хорошо, граница остаётся честной.
- **Разбивайте входное пространство.** Один большой харнесс превращается в несколько по вариантам
  (например, «прямой грант» и «делегированный»). Вместе они покрывают то же множество, но каждый
  помещается в память (VERIFIED_PRIMARY, пилот: 16 ГБ раннер).
- **Строковые функции `str` тяжелее байтовых.** Замена `str::strip_suffix` на байтовый
  `split_last` вернула харнесс в бюджет памяти (VERIFIED_PRIMARY, пилот).

## 3. Ограниченные данные обязаны выражать ошибку

**Ловушка (VERIFIED_PRIMARY, пилот).** Строки ≤ 2 символов, выбранные ради скорости, не могут выразить
случай `/a` против `/ab`. Вдобавок спецификация повторяла код (`starts_with`). В итоге доказательство
подтвердило уязвимость как правильное свойство.

**Правила:**

- Для каждого свойства запишите отличающий случай и поставьте на него `kani::cover!`.
  Например, «байтовый префикс есть, а покрытия по каталогу нет».
- Эталон пишется **другим алгоритмом**, чем код: разбор по компонентам против побайтового
  сравнения.

## 4. Как получить доказательство для любого размера

| Форма кода | Приём | Результат |
|---|---|---|
| Парсер с циклом по байтам | Конечный автомат `step(state, byte)`. Харнесс доказывает **один шаг** для всех состояний × всех байтов, плюс отношение «состояние автомата ↔ состояние спецификации». Индукция по длине даёт любую длину, циклов для развёртки нет | любая длина, 0,2 с (VERIFIED_PRIMARY, пилот). Три внедрённые ошибки → FAILED |
| Структура, которая только растёт (граф происхождения) | Свойство вычисляется при вставке, запрос становится поиском без цикла. Инвариант доказывается индукцией по вставкам в Lean (только ядро Lean, `Relation.TransGen`) | любой размер **на модели**; связь с Rust — исчерпывающий тест (VERIFIED_PRIMARY, пилот) |
| Функция без циклов (`checked_add`) | `kani::any()` по всему типу | весь u32 × u32, 0,16 с (VERIFIED_PRIMARY, шаблон) |
| Цикл по цепочке с `HashMap`/`HashSet` | контракты циклов (`-Z loop-contracts`), `stub_verified` | **не проверено** (UNDERDETERMINED) |

## 5. Окружение и подмены

- **`HashMap` с `RandomState`** упирается в неподдерживаемые системные вызовы. Под `cfg(kani)`
  подменяйте его структурой без хэширования (`VecMap`). Эквивалентность с std подтверждайте
  исчерпывающим дифференциальным тестом (VERIFIED_PRIMARY, пилот).
- **Заглушки как над-аппроксимация.** Заглушка, возвращающая `kani::any()`, делает
  доказательство верным для **любого** ответа заглушённой функции. Это сильнее, а не слабее.
- **Мутанты в коде `cfg(kani)`** тестами не наблюдаемы. Исключайте их в `mutants-exclusions.tsv`
  с обоснованием.
  - Не используйте `..self` в коде спецификации: мутанты вида «удалить поле из struct-выражения»
    не совпадают с исключением по имени файла (VERIFIED_PRIMARY, пилот).
- **Запрет паникующих конструкций** (clippy `indexing_slicing`, `arithmetic_side_effects` и др.)
  убирает класс ошибок, которые Kani иначе ищет перебором.
- **Память.** Харнесс, которому мало 7 ГБ на локальной машине, может пройти на раннере с 16 ГБ.
  Узнать это можно только из логов CI.

## 6. Чего Kani не доказывает

- Свойства Rust-кода в пределах объявленных границ. Граница — часть утверждения. Ответ на вопрос
  «верно ли для любого входа?» — ABSTAIN, если граница не покрывает вход.
- Ничего о том, правильна ли сама спецификация. Это задача независимого эталона и проверки
  версий спецификации (см. `docs/ROADMAP.md`, O4).
