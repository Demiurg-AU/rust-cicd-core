### Как исполнять и обновлять план

Claude начинает каждый сеанс с актуальных main, PR и решений владельца. Выбирает первый незакрытый пункт, ищет готовое решение в репозитории, затем вносит минимальное изменение и проводит проверку. После изменения указывает в существующем PR или issue: SHA, ожидаемый и фактический результат, ссылку на журнал, оставшийся блокер и следующий шаг. На уже выполненный пункт достаточно ссылки. Полный прогон выполняется, когда его требует изменение или политика проекта. Работу можно возобновить по этим записям после прерывания.

Если требуется подпись, изменение административных правил или принятие риска, подготовь владельцу одно конкретное действие и продолжай независимую работу. Исчерпав разрешённые действия, оставь проверяемую точку остановки. Соблюдай действующие правила веток и ревью. Итог каждого этапа — изменение или измерение с воспроизводимым результатом.

### За чем следить

При следующем релизе шаблона или изменении используемого upstream проверь официальные release notes Kani, ClusterFuzzLite, GitHub Actions/rulesets и SLSA. Выбирай изменение, которое отвечает конкретному пробелу из таблицы. Запиши источник и версию, гипотезу, один сравнительный опыт и решение «внедрить / отложить / отклонить». Первые направления — происхождение свидетельств, стоимость проверок PR, независимость спецификаций и доступность формальных харнессов. Тенденция становится изменением шаблона после измеримого результата на нашем коде.

## Цель и критерий готовности

**Цель.** Шаблон CI/CD для Rust, в котором каждое утверждение о безопасности подтверждено
воспроизводимым свидетельством. Каждая проверка доказывает, что она падает на заведомо
плохом входе и по правильной причине (канарейка). Код может писать недоверенный ИИ-агент.

**Готово, когда выполнены все четыре условия:**

1. Каждая строка `threat-model.tsv` — COVERED или OUT_OF_SCOPE. PARTIAL допустим только с остатком,
   который владелец явно принял письменно, со ссылкой на задачу.
2. Каждый контроль из раздела «Перенести в шаблон» работает в шаблоне со своей канарейкой.
3. Шаблон применён к одному внешнему крейту-пилоту без правки скриптов шаблона (решение владельца 2026-11-21:
   два шага).
   - **3a.** Подключение только конфигурацией: ядро гейтов даёт PASS, утверждения с областью model/bounded без
     доказательств дают ABSTAIN, пропуск проверки не засчитывается как PASS.
   - **3b.** Отдельный пакет спецификаций пилота (харнесс Kani, fuzz-цель): это код проверки, у каждого свойства
     утверждение, область входов, допущения, команда и результат; пустой пакет — не PASS.
4. Реестр утверждений отвечает PASS / FAIL / ABSTAIN. «Любой ввод» получает PASS только там,
   где доказательство действительно это покрывает.

(ALISA, Sprint 9.2) не трогаем: ни интеграции, ни правок. Пилотный крейт после завершения

## Отвергнуто (с причиной)

- **Кворум нескольких LLM вместо второго человека.** Слепые пятна у моделей совпадают. Во втором раунде два ответа из шести выдали уверенные «атаки», которые на коде не подтвердились.
- **«Доказательный капитал» агента.** Легко обыграть бессодержательными свойствами.
- **Автоматический рост границ Kani на +1 за ночь.** Упирается в память раньше, чем даёт пользу; нужна смена метода (P6, O5).
- **Подгонка кода под эвристики Scorecard.** Метрика не должна менять код.
